arquitectura

Construido a nivel de kernel, no encima de él

Cuatro decisiones de diseño que hacen de RigelVPN un túnel ligero, auditable y predecible en su rendimiento.

Cifrado criptográfico aislado

AEAD con AES-256-GCM sobre OpenSSL. Cada paquete usa un vector de inicialización dinámico de 96 bits, evitando la reutilización de nonce y garantizando integridad autenticada en cada trama.

EVP_aes_256_gcm

Integración nativa en el kernel

Manipulación directa de interfaces TUN vía /dev/net/tun para inyectar y capturar tráfico IP crudo sin pasar por capas intermedias ni sockets raw adicionales.

ioctl(TUNSETIFF)

Protocolo UDP ligero

Encapsulado sin estado sobre UDP, pensado para bajo retardo. Sin handshakes TCP, sin retransmisiones a nivel de transporte: el control queda en manos de la aplicación.

SOCK_DGRAM

Arquitectura módulo a módulo

Código en C dividido con responsabilidad única: cliente, servidor y librería criptográfica compilan por separado, facilitando auditoría y pruebas unitarias aisladas.

client.c · server.c · crypto.c

demostración

De la compilación al túnel activo

Tres pasos, sin scripts mágicos: compilar, levantar el servidor y validar el aislamiento con namespaces reales.

Compilación directa con GCC, enlazando contra la librería criptográfica de OpenSSL. Sin gestores de paquetes externos ni build systems adicionales.

# compilar cliente y servidor
gcc -Wall -O2 src/client.c src/crypto.c -o bin/rigel-client -lcrypto
gcc -Wall -O2 src/server.c src/crypto.c -o bin/rigel-server -lcrypto

rigel-client   rigel-server   → binarios listos en ./bin

El servidor crea la interfaz TUN, se ancla al namespace de red designado y comienza a escuchar conexiones cifradas sobre UDP.

# requiere CAP_NET_ADMIN
sudo ./bin/rigel-server --iface tun0 --port 51820 --key /etc/rigel/server.key

[OK] tun0 up — 10.8.0.1/24
[OK] AEAD context ready — AES-256-GCM
[OK] listening on udp://0.0.0.0:51820

test_vpn.sh crea dos network namespaces aislados, conecta cliente y servidor a través del túnel y valida el tráfico ICMP cifrado de extremo a extremo.

#!/bin/bash
sudo ip netns add ns-client
sudo ip netns add ns-server
sudo ip netns exec ns-server ./bin/rigel-server --iface tun0 &
sudo ip netns exec ns-client ./bin/rigel-client --connect 10.8.0.1 &
sudo ip netns exec ns-client ping -c 20 10.8.0.1
